Focus: `AreFacesSameDomain` verdict procedure, `PostTreatFF` section-edge fusion, SD face-pair recording + consumers.

## 1. VERDICT

Structurally faithful. Stage order, data structures, and nearly all constants in the spec match the source; the spec's line refs land within a few lines of this tree (`BOPAlgo_PaveFiller_6.cxx` is 4435 L in both). Material errors and omissions found:

- **E1 (error).** Spec Stage 5 says orientation is resolved "via `IsSplitToReverse(faceSp,faceSr)` / `Sense` (normals compared at a shared edge, `SenseFlag`)". `BOPTools_AlgoTools::Sense` (`src/ModelingAlgorithms/TKBO/BOPTools/BOPTools_AlgoTools.cxx:1209-1259`) has **zero callers in the whole source tree** — dead code. Do not port it.
- **E2 (omission, port-blocking).** The verdict is **one-directional and fail-closed**: the interior point is taken from `theF1` only (`BOPTools_AlgoTools.cxx:1153`), and if the hatcher cannot produce it the function returns `false` — "cannot decide" is reported as "not same domain" (`:1155-1159`). There is no `PointNearEdge` fallback here, unlike `IsSplitToReverse(Face,Face)` which does have one (`:1357-1369`). `AreFacesSameDomain(F1,F2)` ≠ `AreFacesSameDomain(F2,F1)` in general.
- **E3 (error).** Spec: "`tolF'` is maxed with the largest non-degenerate edge tolerance of F1" understates it — `aTolEMax` is scanned over **F1's edges only** and then raises **both** `aTolF1` *and* `aTolF2` (`:1174-1196`). F2's own edge tolerances never enter the band.
- **E4 (omission).** Candidate set for `FillSameDomainFaces` is FF-pair faces **filtered by `myDS->HasFaceInfo(nF)`** (`BOPAlgo_Builder_2.cxx:672-679`), and the whole routine early-returns when `InterfFF()` is empty (`:585-590`). The `TangentFaces` flag is **never consulted by the Builder** — SD candidacy is purely "identical edge set". Only `BOPAlgo_CheckerSI.cxx:310-331` gates on `TangentFaces`, and it tests the *original* unsplit faces. Spec INVARIANT 10 ("a pair is either transversal or tangential — the SD-face stage handles the tangential ones") is therefore only half-true: the SD stage cannot see the flag; if imprinting fails to give the two faces identical edge sets, a tangential pair is silently dropped.
- **E5 (error).** Spec Stage 3 says PostTreatFF ends with "transitive closure of `aDMNewSD` chains". It is a **single pass** over the map (`BOPAlgo_PaveFiller_6.cxx:1659-1668`): each value that is itself a key is replaced once. A→B→C→D collapses only partially, and the result is iteration-order dependent.
- **E6 (omission).** Spec's "all new section edges and new vertices from `aMSCPB` go into list `aLS`" hides the traversal direction: the assembly loop runs `k = aNbS → 1` (`:1283`), so `aLS` is the **reverse** of `aMSCPB` insertion order, and the compound of existing edges is appended **last** (`:1313-1316`). `aLS` is further mutated *during* the read-back iteration (compound expansion `:1411-1418`, micro-edge vertices pushed back `:1522-1528`).
- **E7 (latent source bug the spec inherits).** For **points**, the couple records the *loop counter* `i`, not the real interference index: `aCPB.SetIndexInterf(i)` (`:787`) versus `aCPB.SetIndexInterf(aCurInd)` for edges (`:1039`). On a recheck iteration (`i >= aNbFFPrev`, `:733`) the point's stored index is out of range of `aFFs`, and `PostTreatFF` (`:1459-1464`) / `RemoveMicroSectionEdges` (`:4356`) dereference it. Port with `aCurInd` in both places.

Everything else the spec asserts about `PostTreatFF` / `AreFacesSameDomain` that I checked is accurate, including: fast path condition, micro-PB gap/2 tolerance inflation, unused-vertex XOR toggle, existing-edges-in-one-compound rule, `aMEPB` one-PB-per-edge aliasing, `ComputeToleranceOfCB` 11-sample rule, planar-bounded shortcut, same-solid guard, min-DS-index representative, `IsValidBlockForFaces` pcurve shortcut, `PutSEInOtherFaces`, `CorrectToleranceOfSE` 0.1 % hysteresis.

## 2. PORT-CRITICAL DETAILS THE SPEC MISSED

### A. Interior-point choice (`PointInFace`) — the only input to the SD verdict

- `BOPTools_AlgoTools3D.cxx:906-938`: UV box from `IntTools_Context::UVBounds` = `BRepAdaptor_Surface` First/Last U/V of the **face** (`IntTools_Context.cxx:1028-1040`), i.e. the pcurve box, not surface natural bounds. Probe line is the **iso-U line** `U = IntermediatePoint(uMin,uMax)`, direction `gp_Dir2d::D::Y`, origin `(U, 0.)` (`:916-922`).
- `IntermediatePoint(a,b) = (1-0.43213918)*a + 0.43213918*b` (`src/ModelingAlgorithms/TKBO/IntTools/IntTools_Tools.cxx:254-259`, `PAR_T = 0.43213918 = 10·e^-π`). So U sits at **43.2 %** of the U span, not the middle.
- Exactly **two attempts** (`:919-935`): on failure U is mirrored, `U' = uMax - (U - uMin)` (= 56.8 % of the span). Then give up.
- `BOPTools_AlgoTools3D.cxx:992-1066`: the hatcher takes **`Domain(aIH, 1)` — the first domain only** (`:1036`), not the largest. Both endpoints must exist (`iErr=3`/`iErr=4` otherwise, `:1037-1049`). Parameter along the line: `V = IntermediatePoint(v1,v2)` (the `theDt2D` branch is unused from `AreFacesSameDomain`, `:1054-1055`). 3D point = `Surface->D0(P2D)` — the point is on the **surface**, evaluated from UV, never projected.
- Hatcher construction (`IntTools_Context.cxx:343-395`, cached per face, key orientation-insensitive because `TopTools_ShapeMapHasher::operator()(S1,S2)` is `IsSame`): `Geom2dHatch_Intersector(1e-10, 1e-10)`, `Geom2dHatch_Hatcher(intr, Confusion2d=1e-8, Confusion3d=1e-8, true, false)`; the face is forced `TopAbs_FORWARD` (`:367-368`); edges **without a pcurve are skipped** (`:377-381`) and edges with `|u1-u2| < Precision::PConfusion()` (1e-9) are skipped (`:382-385`); each element is added **with the edge's orientation** (`:389`) — that is what defines "inside".

### B. Verdict tolerance and projection (`IsValidPointForFace`)

- `BOPTools_AlgoTools.cxx:1199`: `aTol = aTolF1 + aTolF2 + max(theFuzz, Precision::Confusion())`, with `aTolF1/2` per E3 above. `theFuzz` is the Builder's `myFuzzyValue` (`BOPAlgo_Builder_2.cxx:790`).
- `IntTools_Context.cxx:647-673`: `ProjPS(F2).Perform(P)`; `!IsDone()` ⇒ false; **`if (LowerDistance > aTol) return false`** — strict `>`, unsquared distance, so `dist == aTol` passes; then `LowerDistanceParameters(U,V)` → `IsPointInOnFace` → `StatePointFace != TopAbs_OUT`, i.e. **`TopAbs_ON` counts as same-domain** (`:639-643`).

Distance is therefore measured to the *trimmed UV patch*, not the infinite surface; a point beyond the patch projects onto its border and can still pass if within `aTol`.

- Planar shortcut (`:707-716`, `:780-785`): `bCheckPlanar` is computed on the **original** face (`SurfaceAdaptor().GetType() == GeomAbs_Plane` **and** `ShapeInfo(nF).Box()` not open in any of the 6 directions) and then **inherited by all its splits** (`:726-738`). Two such faces with equal edge sets are declared SD with **no geometric test at all**.
- Bucketing key `BOPTools_Set` (`src/ModelingAlgorithms/TKBO/BOPTools/BOPTools_Set.cxx:120-172`): degenerate edges skipped (`:132-138`); an `INTERNAL`-oriented edge is inserted **twice** (FORWARD + REVERSED copies, `:143-152`); equality = equal count + one-way containment under `IsSame` (`:94-116`) ⇒ **orientation-insensitive but multiplicity-sensitive** (a seam edge, appearing twice in the wire, counts as 2 on both sides). ## 3. PORTING TRAPS

1. **Fail-closed SD verdict.** A hatcher failure, an unbounded first domain, or a face whose edges have no pcurves ⇒ `false`. If your interior-point routine is more robust than OCCT's, you will report SD on pairs OCCT rejects, and vice versa. Keep the "cannot decide ⇒ not SD" policy or you change boolean results.
2. **One-directional test.** Only F1's interior point is tested against F2. Do not "improve" it into a symmetric test: with the edge-set precondition it is nearly always equivalent, but symmetry changes verdicts on degenerate/self-overlapping splits and changes which pairs enter the connexity blocks.
3. **43.2 %, not 50 %.** `IntermediatePoint` (0.43213918) is used for the probe U, for the probe V inside the domain, and for `IsValidBlockForFaces` midpoints (`IntTools_Context.cxx:705`, `:732`). A true midpoint hits symmetric coincidences (seams, symmetry planes) that this constant is chosen to dodge. Same constant, same three places.
4. **First hatch domain only.** For a face with holes the probe line's first (lowest-V) domain is used — the point can land in a thin sliver. Two attempts only, second mirrored. Do not iterate over all domains "for robustness" unless you accept different SD verdicts.
5. **The band is edge-tolerance driven.** `aTol = tolF1' + tolF2' + max(fuzz, 1e-7)` where both `tolF'` were raised by the **max non-degenerate edge tolerance of F1**. In practice this is the dominant term after section edges inflate their vertices/edges — port it, or SD will fail on exactly the geometry that needed it.
6. **`ON` is inside.** `IsPointInOnFace` accepts `TopAbs_ON`; `IsPointInFace` (used by `ComputeVF`) does not. Using the wrong one flips verdicts for points landing on F2's boundary.
7. **Projection is to the trimmed UV patch**, with `Extrema_ExtFlag_MIN` and 1e-12 projector tolerance, and the classifier band is `BRep_Tool::Tolerance(F2)` — three different tolerances in one predicate. Do not collapse them into a single global tol.
8. **SD is edge-topology gated, not geometry gated.** No amount of coincidence makes two faces SD if their edge sets differ (degenerate edges excluded, INTERNAL edges doubled, orientation ignored, multiplicity counted). This is why `PostTreatFF`'s fusion is a *precondition* for SD detection: cross-pair coincident section edges must end up as one shared `TShape` on both faces, or the buckets never collide. A port that keeps per-face copies of coincident section edges will produce zero SD faces and then wrong COMMON/CUT results.
9. **The planar shortcut skips geometry entirely** and is inherited by splits of a bounded planar original. Two coplanar-but-offset bounded planar faces cannot reach it (their edge sets differ), but a port that computes `bCheckPlanar` per split rather than per original will diverge for splits whose own bbox is open/unbounded.
10. **Recording SD only in shape maps.** SD faces are not represented in the intersection DS; `myShapesSD` + rewritten `myImages` + `myOrigins` are the entire contract. Consumers rely on *shape identity* (`BuildRC`'s `Contains`) — so the representative must be the *same object* in both operands' image lists, not an equal-geometry copy.
11. **Orientation is resolved after grouping, per consumer**, by `IsSplitToReverse(Face,Face)`; when both faces share the same surface handle it degenerates to comparing `TopAbs_Orientation` and never looks at geometry. If your port copies surfaces per face, you silently take the expensive branch and can get the opposite answer on closed/periodic surfaces.
12. **`aLS` order and mid-loop mutation in PostTreatFF.** Reverse insertion, compound last, compound children and micro-edge vertices appended while iterating. The fuse result depends on this order (which vertex becomes the SD representative in the nested DS). A port using a set/queue with different ordering will produce different — not necessarily worse, but different — vertex identities, and `aDMNewSD`'s single-pass closure can then leave stale chains.
13. **Single-pass `aDMNewSD` closure** (`:1659-1668`) plus `UpdatePaveBlocks` applying it once means a 3-deep SD chain can leave a pave pointing at an intermediate vertex. If you build a proper union-find, you will *diverge from OCCT in a good way*; verify downstream code does not depend on the stale mapping.
14. **`SetIndexInterf(i)` vs `aCurInd`** (E7): replicate `aCurInd` for points too. Also note that on a recheck pass the FF's points are re-treated from scratch (`:774-791`) and `IsExistingVertex` only consults `aMVOnIn` — previously created section vertices are not in it, so duplicates *are* created deliberately and removed later by the fuse.
15. **Ext-paves-only splitting.** `aPB1->Update(aLPB, false)` (`:892`; `src/ModelingAlgorithms/TKBO/BOPDS/BOPDS_PaveBlock.cxx:249-311`) builds blocks **between consecutive ext paves only** — the curve's own ends are not paves, so a curve with `<2` ext paves yields **no** section edge (that is the `aFFToRecheck` trigger, `:879`, `:894-897`, `:1067-1071`), and the segments outside the extreme paves are discarded, never extrapolated.
16. **`PaveBlock1` lives at index 0 of the curve's PB list** (`BOPDS_Curve.lxx:85-92`) and is removed by `aLPBC.RemoveFirst()` at the end of each curve (`:1065`). On a recheck pass `InitPaveBlock1` only recreates it because the list was emptied; if your port keeps kept-blocks and the workspace in the same container you will re-pave onto a real section block.
17. **Vertex fusion mutates existing shapes.** `MakeSDVertices` rewrites an existing SD vertex's point and tolerance in place, and `PostTreatFF`'s micro-PB inflation calls `UpdateVertex` on vertices that may belong to the original model (guarded only by `NonDestructive` mode upstream). Tolerance growth here is permanent and global; the rollback path (`aMVTol`, `:1075-1095`) exists only for *unused* paves inside `MakeBlocks`.
18. **`aMEPB` aliasing has two side effects**: (a) the same PB handle can appear in several curves' lists, so the per-edge grouping in `UpdateFaceInfo` (`:1736-1742`) can see the same handle twice and build a "common block" of one PB listed twice — dedupe before grouping; (b) `SetOriginalEdge` on the shared PB (`:1645`) is last-writer-wins across old edges.
19. **`ComputeToleranceOfCB` only raises the curve tolerance and is cached per CB** (`:1612-1626`); it samples the *representative* PB's range, so an under-covered non-representative PB does not get its own bound. Downstream, `CorrectToleranceOfSE` may lower the **edge** tolerance back to `aNC.Tolerance()` but never below it, and only for `OriginalEdge() < 0` with the `0.001 * aTolV` gain gate (`:4109-4131`, `:4225`).
20. **A `PostTreatFF` failure kills the whole section stage** (`:1393-1397` → `:1121-1124`). If your unification pass can fail, make it degrade to "no cross-pair fusion" rather than "no section edges".

# Native public routes and OCCT removal

Read-only checkpoint, 2026-10-27. This inventories current code and remaining work; it does not declare C++ acceptance. The original chair Boolean, global mixed offsets, hollowing and full public API matrix remain unaccepted.

| Public operation | Current production route | Native replacement and remaining contract |
|---|---|---|
| Four `BRep::boolean_*` methods | `brep.cpp:3671–3688` → `occt::boolean_operation` | `brep_boolean::apply` already implements the four enum cases. Wire directly after public tests are enabled. It requires closed oriented solids and propagates unresolved section, trim, classification and assembly failures. Original chair acceptance is still pending. |
| `BRep::offset` | `brep.cpp:3691–3693` → `occt::offset` | `brep_offset::shape` exists. One-face offsets, regular smooth boundaries, outward convex joins and restricted inward joins are implemented. It explicitly rejects unsupported mixed/concave joins, focal collapse and unresolved correspondence. This is not a complete general offset replacement yet. |
| `BRep::hollow(openings, thickness)` | `brep.cpp:3333–3334` → `occt::hollow` | No equivalent native public implementation. `brep_thicken::face` accepts one open face and makes ruled walls; it is not the solid-plus-removed-faces operation. |
| `BRep::tessellate(deflection, angle)` | `brep.cpp:3337–3338` → `occt::tessellate` | Native `face_meshes_q` provides shared-edge sampling and trimmed meshing, but quality exhaustion and omitted-face paths need an explicit failure contract before this can promise controlled tessellation. |
| `Intersection::brep_brep` | `intersection.cpp:77–78` → `occt::section` | Native `brep_section::faces` supplies trimmed paired curves and established support overlaps. It does not expose isolated contact points or construct section geometry for all coincident-support cases. Returning only `FaceResult::curves` would silently lose part of the existing contract. |
| `BRep::volume_exact` | `brep.cpp:3237–3239` → `brep_measure::volume` | Already native trimmed-surface integration. Header still incorrectly describes OCCT. |
| `NurbsCurve::offset`, `NurbsSurface::offset` | `nurbscurve.cpp:13`, `nurbssurface.cpp:22` → `nurbs_offset` | Already native; preserve explicit failure for singular/unsupported or unresolved approximations. |
| Public curve/curve, curve/surface, curve/BRep sections | `intersection.cpp:25–74` → native modules | Already native, with incomplete results converted to exceptions. |
| Public surface/surface sections | Native `intersection.cpp` walking/graph/fit path | Already native; certified discovery/continuation and difficult regression validation are still in progress. |

## Gaps that must not be hidden by route changes

`SectionResult` contains isolated points and curves (`intersection.h:27–30`). The current adapter extracts vertices not incident to a returned edge (`occt_backend.cpp:486–505`). OCCT's `BOPAlgo_Section::PerformInternal1` builds vertex images before section assembly (`BOPAlgo_Section.cxx:125–150`). Native `FaceResult` has only curves and support-overlap records. Add native isolated-contact handling and coincident-boundary assembly, or report the unsupported case explicitly; an empty result is not evidence of absence. Preserve face, UV and shared-edge provenance until identity is proved.

OCCT hollowing initializes `BRepOffset_MakeOffset`, adds every requested closing face, and calls `MakeThickSolid` (`BRepOffsetAPI_MakeThickSolid.cxx:31–60`). Native face thickening instead requires `face_count()==1 && solid_count()==0`. A native hollow implementation must remove the selected original faces, offset the retained shell with correct signed orientation, build rim joins for opening boundaries, handle cavities and validate closed material volume. Test the existing box opening case, multiple openings, freeform openings, negative/positive thickness, cavity shells and explicit collapse. Do not substitute face thickening under the old method name.

Native offset constraints are concrete: `brep_offset_join.cpp:522` requires one solid; `check_convex` at 147–161 rejects inward/concave or mixed sharp joins outside the inward path. `brep_offset_inward.cpp:88–91,108,128–131` requires one shell, one outer wire per face, distinct two-face edges without seams/poles, and one edge per adjacent face pair. Global self-interference cleanup, mixed joins, multi-shell/cavity and multi-solid offsets therefore remain substantive work.

For tessellation, radians must become degrees and absolute deflection must become the quality routine's relative control-hull scale. `brep_diagonal` includes every surface CV, so `deflection / brep_diagonal` gives a consistent global factor. However, this conversion alone does not meet the contract: `face_meshes_q` silently continues after `trim_loops` failure, `strip_segments` stops at 4096, `span_subdivisions` caps at 64, and trimmed `refine` stops after eight rounds or 200000 vertices without returning a failure flag (`brep.cpp:1834–1846,3440`; `nurbssurface_trimmed.cpp:177–205,2602–2630`). A controlled native wrapper must verify every active face is present and check remaining deflection/normal error after bounded refinement, failing explicitly if unresolved. Existing display `mesh()` can retain its own documented approximation semantics. Do not change CDT tolerances to enforce mesh-volume identity.

## Dependency removal sequence

1. Enable public native regression coverage before replacing calls. The large public Boolean/offset/hollow/chair block in `brep_test.cpp:745` is currently hidden behind `SESSION_WITH_OCCT`; it must be migrated or enabled, not silently deleted. Keep current native component tests and add public wrapper assertions.
2. Wire the four Boolean methods and supported BRep offsets directly to their native modules, preserving errors and tolerance arguments. Complete native section contacts/coincident geometry, hollowing and controlled meshing as above. Unimplemented cases must fail with a native limitation, without an OCCT suggestion or fallback; such explicit failure is not completion of the user's requested feature.
3. Remove `occt_backend.h/.cpp` from production once references are gone. CMake's `file(GLOB PROJECT_SOURCES "src/*.cpp")` currently includes even the OFF-mode stub adapter. Remove the entire production `SESSION_WITH_OCCT` option/include/link block (`CMakeLists.txt:355–382`), its public compile definition and `if(NOT SESSION_WITH_OCCT)` condition around native targets. Delete obsolete OCCT wording from public headers.
4. Keep only independent oracle programs outside the kernel. `examples/occt_reference/CMakeLists.txt` is already a separate project linking OCCT and the JSON headers, without `session_core`; the separate OCP scripts are also suitable references. The old `geometry_evidence` target depends on the production backend and must be retired or rewritten as an explicitly separate oracle. Update `native_geometry_gallery.py` to check absence of a production OCCT dependency rather than require the removed cache variable to equal OFF.
5. Reconfigure a fresh native build with no OCCT include/library paths and no `SESSION_WITH_OCCT` definition. Inspect actual compilation and link commands, then run the public API matrix and original chair operations against independent saved oracle geometry/volumes. Search production source and generated link inputs for `occt_backend`, `occt::`, `OpenCASCADE`, `SESSION_WITH_OCCT` and OCCT libraries. Saved reference data and oracle-only projects may still contain these names. Only then update acceptance status and consider Rust/Python ports.

No production source or CMake edits were made for this audit.
